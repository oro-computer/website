# `std::runtime::z3`

Status: **Implemented raw bindings**. `std::runtime::z3` exposes the full Z3 C
API needed for low-level solver integration from Silk.

## Exported API

### Binding model

`std::runtime::z3` is a direct `ext` surface:

- opaque Z3 handles are `u64`
- `Z3_string` and other C string pointers are `u64`
- pointer parameters and pointer arrays are passed as `u64`

The module exports the original `Z3_*` names rather than wrapping them behind a
Silk-specific adapter layer.

## Examples

### Check a trivial satisfiable formula

```silk
import z3 from "std/runtime/z3";

export fn main () -> int {
  let cfg: z3::Z3_config = z3::Z3_mk_config();
  if cfg == 0 {
    return 1;
  }

  let ctx: z3::Z3_context = z3::Z3_mk_context_rc(cfg);
  z3::Z3_del_config(cfg);
  if ctx == 0 {
    return 2;
  }

  let solver: z3::Z3_solver = z3::Z3_mk_solver(ctx);
  if solver == 0 {
    z3::Z3_del_context(ctx);
    return 3;
  }
  z3::Z3_solver_inc_ref(ctx, solver);

  let truth: z3::Z3_ast = z3::Z3_mk_true(ctx);
  z3::Z3_solver_assert(ctx, solver, truth);

  let result: z3::Z3_lbool = z3::Z3_solver_check(ctx, solver);

  z3::Z3_solver_dec_ref(ctx, solver);
  z3::Z3_del_context(ctx);

  return if result == z3::Z3_L_TRUE { 0 } else { 4 };
}
```

## Considerations

- This module is intentionally low-level. It does not track ownership or
  reference counts for you.
- Pair every `*_inc_ref` with the matching `*_dec_ref`, and free contexts,
  solvers, params, or other owning handles using the correct Z3 API.
- Many Z3 functions return borrowed `const char *` pointers. Convert them with
  `std::ffi::c::cstr_borrow(ptr)` and treat the resulting Silk `string` as a
  borrowed view.
- On the hosted `linux/x86_64` baseline, `silk build` auto-links the vendored
  `libz3.a` and the required runtime support libraries when this module is in
  the module set.
- The current auto-link behavior is hosted-baseline specific. If you embed Z3
  elsewhere, ensure the archive and runtime dependencies are available to the
  final link.

## Design goals

- Preserve the upstream Z3 naming and calling model so porting C examples is
  straightforward.
- Expose the complete raw API surface for advanced users and wrapper authors.
- Keep higher-level ergonomics separate from the low-level FFI layer.
