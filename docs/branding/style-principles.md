## Website Style Principles
| Theme                  | Description                                                              | Application                         |
| ---------------------- | ------------------------------------------------------------------------ | ----------------------------------- |
| **Symmetry & Balance** | Every layout mirrors geometric clarity.                                  | Grids, iconography, spacing rhythm. |
| **Refined Light**      | Use gradients and glows sparingly to imply intelligence, not excess.     | Hero backgrounds, hover states.     |
| **Organic Geometry**   | Petal shapes recur subtly in buttons, section dividers, and transitions. | SVG motifs and animations.          |
| **Technical Grace**    | Combine elegance with function - performance meets design.               | Code samples, runtime previews.     |


## Website direction

Lead with what a developer can build. Oro Runtime and Silk are the primary
technology initiatives. Use short, concrete descriptions and distinguish setup
requirements from application workflows. A dark canvas, generous negative space,
clear product hierarchy, and restrained geometric artwork carry the visual tone.
The reference sites are technology.spotify.com (product clarity and dark composition)
and reflection.ai (typographic scale and spacious rhythm); retain Oro's identity.

## Documentation voice

Give each page one job. Start with the reader's task, show an example, and say
what happens next. Keep paragraphs short and explain each concept once, where
the reader first needs it. Link to related guides and references instead of
repeating setup, background, API inventories, or optional features.

Learning chapters should tell a connected story: build something, try it, then
extend it. Keep commands, filenames, prerequisites, expected results, and any
limitation needed to use the example correctly. Show only the new code in a
continuing chapter and name exactly where it goes. Keep standalone examples
complete. Reference pages may be detailed; their introductions should still
answer the immediate question before presenting the full specification.
