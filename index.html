Oro Runtime

Ship web code as native desktop, mobile, and edge apps.

Use ordinary HTML, CSS, and JavaScript with explicit oro:* modules for windows, files, notifications, service workers, storage, workers, updates, and host integration.

  • Service workers Keep the app shell available offline and coordinate background work.
  • Filesystem access Read and write through explicit sandboxed paths and native pickers.
  • Notifications Send useful native alerts from ordinary JavaScript flows.
  • Window management Create, focus, size, and coordinate multiple app windows.

Silk

Write explicit systems code with formal verification built in.

Silk keeps imports, targets, ABI boundaries, async work, and proofs visible in the source so reviewers can reason about what runs, what links, and what must hold.

  • Module system Use file-backed imports, package exports, and explicit namespaces.
  • ABI and FFI Keep host boundaries visible with direct symbol imports and exports.
  • Standard library Build on documented modules for IO, paths, processes, data, and time.
  • Formal Silk Attach requirements, assurances, invariants, and proof obligations.
Overview Quick start 2026 spec 
package app;

import { println } from "std/io";

interface Sink {
  fn write(line: string) -> void;
}

struct ConsoleSink { prefix: string, }

impl ConsoleSink as Sink {
  fn write(self: &ConsoleSink, line: string) -> void {
    println("[{}] {}", self.prefix, line);
  }
}

struct Job {
  name: string,
  retries: int? = None,
}

impl Job {
  fn attempts(self: &Job) -> int {
    return self.retries ?? 1;
  }
}

fn platform () -> string {
  if attr(os="linux") { return "linux"; }
  if attr(target="wasm32-wasi") { return "wasi"; }
  return "host";
}

async fn configured_job () -> string? {
  return Some("sync-cache");
}

task fn run(job: Job) -> Result(int, string) {
  if job.name == "" { return Err("missing job name"); }
  return Ok(job.attempts());
}

async fn main () -> int {
  let sink = ConsoleSink{ prefix: platform() };
  let name: string? = await configured_job();
  let job = Job{ name: name ?? "", retries: Some(3) };
  let handle = run(job);

  task {
    let results: Result(int, string)[] = yield * handle;
    match results[0] {
      Ok(count) => {
        if count > 1 {
          sink.write("completed after retry budget");
        } else {
          sink.write("completed");
        }
      },
      Err(message) => sink.write(message),
    }
  }

  return 0;
}

Virtnosis

Inspect libvirt infrastructure without mutating host or guest state.

Virtnosis is a read-only local control plane for operators who need bounded scans, redacted output, explicit degraded-state reporting, and stable machine-consumable findings.

  • Read-only scans Inspect libvirt state without mutating hosts or guests.
  • Redacted output Emit reports that can move through logs, CI, and tickets.
  • Operator CLI Use agent and vnactl workflows for local control.
  • Stable findings Surface degraded states as machine-consumable signals.
Overview Start CLI 
# Start a local, bounded control plane.
virtnosis-agent \
  --listen unix:///run/virtnosis/agent.sock \
  --scan-timeout-ms 30000 \
  --verbose

# Confirm which daemon and scanner build will answer.
vnactl status \
  --connect unix:///run/virtnosis/agent.sock \
  --raw-json

# Inspect libvirt without changing host or guest state.
vnactl scan \
  --connect unix:///run/virtnosis/agent.sock \
  --socket /var/run/libvirt/libvirt-sock \
  --uri qemu:///system \
  --deep \
  --deep-enum-max 32 \
  --deep-resolve-max 8 \
  --confirm-xml \
  --redact \
  -f json \
  > scan.redacted.json

# Automation reads stable summary and coverage fields.
jq '.scan.summary,
    .scan.domains.coverage,
    .scan.risks_full.total' scan.redacted.json
